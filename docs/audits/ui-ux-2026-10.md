# UI/UX audit — October 2026

Status: Phase A of the rebuild plan in `docs/uiux-rebuild-prompt.md`. This document is the gate
before any rebuild work starts. Findings drive Phase B priorities; the strengths list is what the
rebuild must not break.

## Method

Every route was rendered live against a disposable backend (fresh SQLite database, throwaway
account seeded with three launch drafts across Pump.fun/Clanker/Four.meme, managed wallets on
Solana/Base, and a tracker entry) and screenshotted at 1440×900; the two densest screens were
re-shot at 380×800. The backend ran without chain RPCs on purpose, so unavailable-data states are
visible and auditable. Admin was not rendered live (needs a configured superadmin) and is judged
from code. Code-level review covered `styles.css` (1,237 lines), `components/ui.tsx`, page
components, and the domain modules.

## Strengths — do not break these

- The preview-then-confirm discipline is visible in the UI's own copy everywhere; keep it prominent.
- Honesty markers work: "—" for unknown balances with "load balances to see", "Unavailable ≠ zero",
  "mainnet · real money" chips, "Test signer · no real funds" pill.
- Accessibility fundamentals are real: skip links, focus-visible rings, focus-trapped modals, table
  captions, 44px targets.
- Responsive behavior at 380px is genuinely good: tables collapse into card lists, stat grids stack.
- Tabular numerals + IBM Plex pairing reads like a terminal, which is the right identity.
- Empty states ("No wallets attached", "No wallets on these networks yet") explain the next action.

## Design-system gap list (Phase B inputs)

1. **Elevation**: cards are border-defined only; no shadow/depth tokens — hierarchy flattens on
   dense screens. Add 2–3 elevation levels.
2. **Motion tokens**: durations/easings are inline or absent; no reduced-motion coverage for
   transitions (only for existing CSS animations).
3. **Skeleton component**: page-level gray blocks; needs shimmer, per-region variants, and labels.
4. **Empty-state consistency**: `Empty` exists in ui.tsx but several screens hand-roll variants.
5. **Brand-mark fallback**: undefined treatment when an asset is missing (the empty-square bug).
6. **Scrollbar styling**: unstyled overflow on tables/matrices.
7. **Status chips**: no size/weight variant for constant-vs-varying state (the "Managed" noise).
8. **Metric cells**: no shared component enforcing the "—" vs 0 convention or unit styling.

## Phase B priority order

1. Token + primitive upgrade (elevation, motion tokens, skeleton, metric cell, mark fallback) —
   everything else builds on it.
2. Workspace (finding 1, 4, 5) — the highest-traffic screen.
3. Wallets (finding 6, 14) — the money screen.
4. Launches + create-modal flow (finding 2, 12).
5. Dashboard (finding 8) and Settings/Networks (7, 3, 10).
6. Motion pass with @react-spring/web across modals, lists, job progress (9).
7. Naming sweep (4) and code-health items (11) as part of each screen's rebuild.

## Audit limitations

- Admin was reviewed from code only (superadmin gating prevented a live seeded render).
- Live RPC-less rendering means market charts, GMGN terminal, and holder data were audited as
  error/empty states, not with live data; those states are part of the audit (they are what users
  see on RPC hiccups) but live-data layouts were checked from code.
- No automated axe run was performed; accessibility was assessed manually against the checklist.
